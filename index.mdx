## Overview

The RobotForge Python SDK provides comprehensive observability and telemetry for AI applications, enabling you to trace model calls, tool executions, and agent actions with minimal code changes. The SDK supports both synchronous and asynchronous operations, offering flexible integration patterns including context managers, decorators, and manual event creation.

<Info>
The SDK works with any LLM provider or AI tool. While examples may reference specific providers like OpenAI, the SDK is provider-agnostic and designed for maximum flexibility.
</Info>

### Key features

- **Universal compatibility** - Works with any LLM provider (OpenAI, Anthropic, Cohere, custom models)
- **Multiple integration patterns** - Context managers, decorators, and manual instrumentation
- **Async and sync support** - Full support for both async/await and synchronous code
- **Automatic token tracking** - Built-in token counting and cost calculation
- **Distributed tracing** - Track complete execution chains across model calls and tools
- **Production-ready** - Automatic batching, retries, and error handling

```bash
pip install robotforge-python-sdk
```

- Python 3.8 or higher
- `aiohttp` for async operations

### Spans and traces

A **span** represents a single unit of work in your AI application, such as a model call or tool execution. Multiple related spans form a **trace**, which represents the complete execution path of a request.

```python
# Parent span (trace root)
async with client.trace_model_call(provider="openai", model="gpt-4") as parent_span:
    parent_span.set_input("Analyze sentiment")
    
    # Child span (part of same trace)
    async with client.trace_tool_execution(tool_name="sentiment_analyzer") as child_span:
        child_span.set_input({"text": "This is great!"})
        result = await analyze_sentiment("This is great!")
        child_span.set_output(result)
    
    parent_span.set_output("Positive sentiment detected")
```

## Integration patterns

### Context managers

Context managers provide automatic span lifecycle management with proper timing and error handling.

#### Async context managers

<CodeGroup>
```python Model calls

        provider="anthropic",
        model="claude-3-opus"
    ) as span:
        span.set_input(prompt)
        
        response = await anthropic_client.messages.create(
            model="claude-3-opus-20240229",

        span.set_usage_details({
            'prompt_tokens': response.usage.input_tokens,
            'completion_tokens': response.usage.output_tokens,
            'total_tokens': response.usage.input_tokens + response.usage.output_tokens

```

```python Tool execution
async def search_web(query: str):
```

### Decorators

Decorators provide zero-boilerplate instrumentation for functions that should always be traced.

#### Model call decorators

<CodeGroup>
```python Async decorator
@client.trace_model_call_decorator(
    provider="openai",
    model="gpt-4",
    capture_input=True,
    capture_output=True
)
async def summarize_document(document: str) -> str:
    response = await openai_client.chat.completions.create(
        model="gpt-4",
        messages=[{
            "role": "user",
            "content": f"Summarize this document:\n\n{document}"
        }]
    )
    return response.choices[0].message.content

# Function is automatically traced
summary = await summarize_document(long_document)
```

```python Sync decorator
@client.trace_model_call_decorator(
```

## Span API reference

All span types (`ModelCallSpan`, `ToolExecutionSpan`, `AgentActionSpan`) inherit from the base `ObservationSpan` class and support common operations.

### Common span methods

#### set_input

Set the input data for the span.

```python
span.set_input("What is the capital of France?")

# Or with structured data
span.set_input({
    "prompt": "Analyze this data",
    "parameters": {"temperature": 0.7}
})
```

<ParamField path="input" type="any">
Input data for the operation. Can be a string, dictionary, list, or any JSON-serializable type.
</ParamField>

#### set_output

Set the output data for the span.

```python
span.set_output("The capital of France is Paris.")

# Or with structured data
span.set_output({
    "result": "Analysis complete",
    "findings": ["finding1", "finding2"]
})
```

<ParamField path="output" type="any">
Output data from the operation. Can be a string, dictionary, list, or any JSON-serializable type.
</ParamField>

#### set_metadata

Add custom metadata to the span.

```python
span.set_metadata("user_tier", "premium")

# Or set multiple metadata fields
span.update(metadata={
    "user_tier": "premium",
    "region": "us-east-1",
    "experiment_id": "exp_123"
})
```

<ParamField path="key" type="string">
Metadata key name.
</ParamField>

<ParamField path="value" type="any">
Metadata value. Must be JSON-serializable.
</ParamField>

#### set_status

Set the execution status of the span.

```python
from telemetry_sdk.client import EventStatus

span.set_status(EventStatus.SUCCESS)
span.set_status(EventStatus.ERROR)
span.set_status(EventStatus.PENDING)
```

<ParamField path="status" type="EventStatus">
Status enum value: `SUCCESS`, `ERROR`, or `PENDING`.
</ParamField>

#### set_error

Mark the span as failed and capture exception details.

```python
try:
    result = await risky_operation()
except Exception as e:
    span.set_error(e)
    raise
```

<ParamField path="error" type="Exception">
Python exception object to capture.
</ParamField>

<Note>
When using context managers, exceptions are automatically captured. You only need to call `set_error` explicitly when manually managing span lifecycle.
</Note>

### Model call span methods

#### set_usage_details

Record token usage information for the model call.

```python
span.set_usage_details({
    'prompt_tokens': 150,
    'completion_tokens': 75,
    'total_tokens': 225
})
```

<ResponseField name="prompt_tokens" type="integer">
Number of tokens in the input prompt.
</ResponseField>

<ResponseField name="completion_tokens" type="integer">
Number of tokens in the generated completion.
</ResponseField>

<ResponseField name="total_tokens" type="integer">
Total tokens used (prompt + completion). Auto-calculated if not provided.
</ResponseField>

#### set_cost_details

Record cost information for the model call.

```python
# Simple cost
span.set_cost_details(0.0045)

# Detailed cost breakdown
span.set_cost_details({
    'prompt_cost': 0.003,
    'completion_cost': 0.0015,
    'total_cost': 0.0045
})
```

<ParamField path="cost" type="float | dict">
Either a single float for total cost, or a dictionary with detailed cost breakdown.
</ParamField>

<Tip>
The SDK includes built-in pricing information for popular models. When you specify `provider` and `model`, costs can be calculated automatically from usage details.
</Tip>

#### set_model_parameters

Record model configuration parameters.

```python
span.set_model_parameters({
    'temperature': 0.7,
    'top_p': 0.9,
    'max_tokens': 500,
    'frequency_penalty': 0.0,
    'presence_penalty': 0.0
})
```

<ParamField path="params" type="dict">
Dictionary of model parameters like temperature, top_p, max_tokens, etc.
</ParamField>

#### set_finish_reason

Record why the model stopped generating.

```python
span.set_finish_reason("stop")  # Natural completion
span.set_finish_reason("length")  # Hit max tokens
span.set_finish_reason("content_filter")  # Content policy violation
```

<ParamField path="reason" type="string">
Completion finish reason: `stop`, `length`, `content_filter`, or provider-specific values.
</ParamField>

Update multiple model-specific fields at once.

## Advanced usage

### Nested tracing

Create hierarchical traces by nesting context managers to represent parent-child relationships.

```python
async def complex_workflow(user_query: str):
    # Parent span - represents the entire workflow
    async with client.trace_agent_action(
        action_type="workflow_orchestration"
    ) as workflow_span:
        workflow_span.set_input({"query": user_query})
        
        # Child span 1 - Model call for query understanding
        async with client.trace_model_call(
            provider="openai",
            model="gpt-4"
        ) as understanding_span:
            understanding_span.set_input(user_query)
            intent = await analyze_intent(user_query)
            understanding_span.set_output(intent)
        
        # Child span 2 - Tool execution based on intent
        async with client.trace_tool_execution(
            tool_name="data_retrieval"
        ) as tool_span:
            tool_span.set_input({"intent": intent})
            data = await retrieve_data(intent)
            tool_span.set_output(data)
        
        # Child span 3 - Model call for response generation
        async with client.trace_model_call(
            provider="openai",
            model="gpt-4"
        ) as generation_span:
            generation_span.set_input({
                "intent": intent,
                "data": data
            })
            response = await generate_response(intent, data)
            generation_span.set_output(response)
        
        workflow_span.set_output(response)
        return response
```

<Check>
The SDK automatically manages trace IDs and parent-child relationships when using nested context managers.
</Check>

### Parallel operations

Track multiple concurrent operations within the same trace.

```python
async def process_multiple_prompts(prompts: list[str]):
    async with client.trace_agent_action(
        action_type="batch_processing"
    ) as batch_span:
        batch_span.set_input({"prompt_count": len(prompts)})
        
        # Process prompts in parallel, all linked to parent span
        async def process_single(prompt: str, index: int):
            async with client.trace_model_call(
                provider="openai",
                model="gpt-3.5-turbo"
            ) as span:
                span.set_input(prompt)
                span.set_metadata("batch_index", index)
                
                result = await openai_client.chat.completions.create(
                    model="gpt-3.5-turbo",
                    messages=[{"role": "user", "content": prompt}]
                )
                
                span.set_output(result.choices[0].message.content)
                return result.choices[0].message.content
        
        # Execute all in parallel
        results = await asyncio.gather(*[
            process_single(prompt, i) 
            for i, prompt in enumerate(prompts)
        ])
        
        batch_span.set_output({
            "processed": len(results),
            "results": results
        })
        
        return results

# Process multiple prompts concurrently
prompts = [
    "Explain photosynthesis",
    "What is quantum entanglement?",
    "Describe the water cycle"
]
results = await process_multiple_prompts(prompts)
await client.flush()
```

### Error handling

The SDK provides robust error handling with automatic retry logic and graceful degradation.

```python
async def resilient_model_call(prompt: str):
    async with client.trace_model_call(
        provider="openai",
        model="gpt-4"
    ) as span:
        span.set_input(prompt)
        
        try:
            response = await openai_client.chat.completions.create(
                model="gpt-4",
                messages=[{"role": "user", "content": prompt}]
            )
            span.set_output(response.choices[0].message.content)
            return response.choices[0].message.content
            
        except openai.RateLimitError as e:
            span.set_error(e)
            span.set_metadata("error_type", "rate_limit")
            span.set_status(EventStatus.ERROR)
            raise
            
        except openai.APIError as e:
            span.set_error(e)
            span.set_metadata("error_type", "api_error")
            span.set_status(EventStatus.ERROR)
            raise
            
        except Exception as e:
            span.set_error(e)
            span.set_metadata("error_type", "unknown")
            span.set_status(EventStatus.ERROR)
            raise
```

<Warning>
Always re-raise exceptions after capturing them in spans to maintain normal error propagation in your application.
</Warning>

### Batching and flushing

The SDK automatically batches events for efficient transmission, but you can control this behavior.

<Tabs>
<Tab title="Async flushing">
```python
# Manual flush to ensure events are sent
await client.flush()

# Flush with timeout
await client.flush(timeout=10.0)

# Check if there are pending events
if client.has_pending_events():
    await client.flush()
```
</Tab>


## Best practices

### Performance optimization

<AccordionGroup>
<Accordion title="Use appropriate batch sizes">
Configure batch size based on your application's throughput:

- **Low volume** (< 10 events/sec): `batch_size=5`, `flush_interval=10.0`
- **Medium volume** (10-100 events/sec): `batch_size=10`, `flush_interval=5.0`
- **High volume** (> 100 events/sec): `batch_size=50`, `flush_interval=2.0`

```python
client = TelemetryClient(
    api_key=api_key,
    user_id=user_id,
    application_id=application_id,
    batch_size=50,  # Higher for high-volume scenarios
    flush_interval=2.0
)
```
</Accordion>

<Accordion title="Minimize span creation overhead">
Create spans only for operations you need to monitor. Not every function needs instrumentation.

```python
# Good: Trace important operations
async with client.trace_model_call(...) as span:
    result = await expensive_llm_operation()

# Avoid: Don't trace trivial operations
# No need to trace simple string formatting
formatted = f"Hello {name}"
```
</Accordion>

<Accordion title="Reuse client instances">
Create one client instance per application and reuse it across requests.

```python
# Good: Single client instance
class Application:
    def __init__(self):
        self.telemetry = TelemetryClient(...)
    
    async def handle_request(self):
        async with self.telemetry.trace_model_call(...) as span:
            pass

# Avoid: Creating clients repeatedly
async def handle_request():
    client = TelemetryClient(...)  # Creates new connection pool
```
</Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
<Accordion title="Events not appearing in dashboard">
**Symptoms**: Telemetry events are created but don't show up in the RobotForge dashboard.

**Solutions**:

1. Ensure you call `flush()` to send batched events:
```python
await client.flush()
# or for sync code:
client.flush_sync()
```

2. Check for authentication errors in logs:
```python
client = TelemetryClient(
    api_key=api_key,
    user_id=user_id,
    application_id=application_id,
    debug=True  # Enable debug logging
)
```

3. Verify your API key is valid and active in organization settings.

4. Check network connectivity and firewall rules for outbound HTTPS.
</Accordion>

<Accordion title="High latency or performance impact">
**Symptoms**: Application slows down significantly after adding telemetry.

**Solutions**:

1. Increase batch size to reduce HTTP request frequency:
```python
client = TelemetryClient(
    batch_size=100,  # Larger batches
    flush_interval=10.0  # Less frequent flushes
)
```

2. Verify you're not creating spans for every trivial operation.

3. Use decorators instead of manual context managers for better performance:
```python
# Faster: decorator with minimal overhead
@client.trace_model_call_decorator(provider="openai", model="gpt-4")
async def my_function():
    pass
```

4. Consider using sampling for high-volume scenarios:
```python
import random

if random.random() < 0.1:  # Sample 10% of requests
    async with client.trace_model_call(...) as span:
        pass
```
</Accordion>

<Accordion title="Authentication errors">
**Symptoms**: Getting 401 Unauthorized or 403 Forbidden errors.

**Solutions**:

1. Verify API key is correctly set:
```python
import os
print(f"API Key loaded: {os.getenv('ROBOTFORGE_API_KEY')[:10]}...")
```

2. Check API key hasn't been revoked in organization settings.

3. Ensure API key has proper permissions for your organization/project.

4. Verify environment variables are loaded correctly:
```python
from dotenv import load_dotenv
load_dotenv()  # Must be called before creating client
```
</Accordion>

<Accordion title="Memory leaks with long-running applications">
**Symptoms**: Memory usage continuously increases over time.

**Solutions**:

1. Ensure proper cleanup of client resources:
```python
async def main():
    client = TelemetryClient(...)
    try:
        # Application logic
        pass
    finally:
        await client.flush()
        await client.close()  # Clean up connection pool
```

2. Configure maximum queue size to prevent unbounded growth:
```python
client = TelemetryClient(
    max_queue_size=1000  # Drop events if queue exceeds this size
)
```

3. Monitor pending event count:
```python
if client.has_pending_events():
    count = client.get_pending_count()
    if count > 1000:
        logger.warning(f"Large pending event backlog: {count}")
```
</Accordion>

<Accordion title="Type errors with MyPy or static analysis">
**Symptoms**: Type checker reports errors when using SDK types.

**Solutions**:

1. Install type stubs if available:
```bash
pip install types-robotforge-python-sdk
```

2. Import proper types from SDK:
```python
from telemetry_sdk.client import TelemetryClient, EventStatus
from typing import Optional, Dict, Any

client: TelemetryClient = TelemetryClient(...)
```

3. Use type: ignore comments for known issues:
```python
result = await some_operation()  # type: ignore[misc]
```
</Accordion>
</AccordionGroup>

```python FastAPI application
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import telemetry_sdk
import openai
import os

app = FastAPI()

# Initialize telemetry client
telemetry_client = telemetry_sdk.quick_setup(
    api_key=os.getenv("ROBOTFORGE_API_KEY"),
    user_id="api_service",
    application_id="chatbot_api",
    set_as_default=True
)

# Initialize OpenAI client
openai_client = openai.AsyncOpenAI(
    api_key=os.getenv("OPENAI_API_KEY")
)

class ChatRequest(BaseModel):
    message: str
    user_id: str

class ChatResponse(BaseModel):
    response: str
    tokens_used: int

@app.post("/chat", response_model=ChatResponse)
async def chat_endpoint(request: ChatRequest):
    async with telemetry_client.trace_model_call(
        provider="openai",
        model="gpt-4"
    ) as span:
        # Set request metadata
        span.set_input(request.message)
        span.set_metadata("user_id", request.user_id)
        span.set_metadata("endpoint", "/chat")
        
        try:
            # Make OpenAI call
            response = await openai_client.chat.completions.create(
                model="gpt-4",
                messages=[
                    {"role": "system", "content": "You are a helpful assistant."},
                    {"role": "user", "content": request.message}
                ]
            )
            
            # Capture telemetry
            message_content = response.choices[0].message.content
            span.set_output(message_content)
            span.set_usage_details({
                'prompt_tokens': response.usage.prompt_tokens,
                'completion_tokens': response.usage.completion_tokens,
                'total_tokens': response.usage.total_tokens
            })
            
            return ChatResponse(
                response=message_content,
                tokens_used=response.usage.total_tokens
            )
            
        except Exception as e:
            span.set_error(e)
            raise HTTPException(status_code=500, detail=str(e))

@app.on_event("shutdown")
async def shutdown_event():
    await telemetry_client.flush()
    await telemetry_client.close()
```

```python Batch processing script
import asyncio
import os
from pathlib import Path
import telemetry_sdk
import anthropic

async def process_documents_batch(documents: list[str]):
    # Initialize clients
    telemetry_client = telemetry_sdk.quick_setup(
        api_key=os.getenv("ROBOTFORGE_API_KEY"),
        user_id="batch_processor",
        application_id="document_analysis",
        batch_size=50,  # Higher batch size for bulk processing
        flush_interval=5.0
    )
    
    anthropic_client = anthropic.AsyncAnthropic(
        api_key=os.getenv("ANTHROPIC_API_KEY")
    )
    
    async def analyze_document(doc_path: str, index: int):
        async with telemetry_client.trace_model_call(
            provider="anthropic",
            model="claude-3-sonnet"
        ) as span:
            span.set_metadata("document_index", index)
            span.set_metadata("document_path", doc_path)
            
            # Read document
            with open(doc_path, 'r') as f:
                content = f.read()
            
            span.set_input({"document": doc_path, "length": len(content)})
            
            # Analyze with Claude
            response = await anthropic_client.messages.create(
                model="claude-3-sonnet-20240229",
                max_tokens=1000,
                messages=[{
                    "role": "user",
                    "content": f"Analyze this document:\n\n{content}"
                }]
            )
            
            analysis = response.content[0].text
            span.set_output({"analysis": analysis})
            span.set_usage_details({
                'prompt_tokens': response.usage.input_tokens,
                'completion_tokens': response.usage.output_tokens,
                'total_tokens': response.usage.input_tokens + response.usage.output_tokens
            })
            
            return analysis
    
    # Process all documents in parallel
    results = await asyncio.gather(*[
        analyze_document(doc, i) 
        for i, doc in enumerate(documents)
    ])
    
    # Ensure all telemetry is sent
    await telemetry_client.flush()
    await telemetry_client.close()
    
    return results

# Run batch processing
documents = [str(p) for p in Path("./documents").glob("*.txt")]
results = asyncio.run(process_documents_batch(documents))
```

```python Agent workflow
import asyncio
import telemetry_sdk
import openai
import os

class ResearchAgent:
    def __init__(self):
        self.telemetry = telemetry_sdk.quick_setup(
            api_key=os.getenv("ROBOTFORGE_API_KEY"),
            user_id="research_agent",
            application_id="autonomous_researcher"
        )
        self.openai_client = openai.AsyncOpenAI()
    
    async def research_topic(self, topic: str):
        async with self.telemetry.trace_agent_action(
            action_type="research_workflow"
        ) as workflow_span:
            workflow_span.set_input({"topic": topic})
            
            # Step 1: Generate research questions
            questions = await self._generate_questions(topic)
            
            # Step 2: Answer each question
            answers = []
            for question in questions:
                answer = await self._answer_question(question)
                answers.append(answer)
            
            # Step 3: Synthesize findings
            synthesis = await self._synthesize(topic, answers)
            
            workflow_span.set_output({
                "topic": topic,
                "questions_explored": len(questions),
                "synthesis": synthesis
            })
            
            return synthesis
    
    async def _generate_questions(self, topic: str):
        async with self.telemetry.trace_model_call(
            provider="openai",
            model="gpt-4"
        ) as span:
            span.set_input(f"Generate research questions about: {topic}")
            span.update(
                agent_name="question_generator",
                thought_process="Breaking down topic into research questions"
            )
            
            response = await self.openai_client.chat.completions.create(
                model="gpt-4",
                messages=[{
                    "role": "user",
                    "content": f"Generate 3 research questions about {topic}"
                }]
            )
            
            questions = response.choices[0].message.content.split('\n')
            span.set_output(questions)
            return questions
    
    async def _answer_question(self, question: str):
        async with self.telemetry.trace_tool_execution(
            tool_name="web_search"
        ) as span:
            span.set_input({"query": question})
            
            # Simulate web search
            await asyncio.sleep(0.5)
            answer = f"Research findings for: {question}"
            
            span.set_output(answer)
            return answer
    
    async def _synthesize(self, topic: str, answers: list[str]):
        async with self.telemetry.trace_model_call(
            provider="openai",
            model="gpt-4"
        ) as span:
            span.set_input({
                "topic": topic,
                "findings": answers
            })
            
            response = await self.openai_client.chat.completions.create(
                model="gpt-4",
                messages=[{
                    "role": "user",
                    "content": f"Synthesize these findings about {topic}:\n\n" + 
                              "\n".join(answers)
                }]
            )
            
            synthesis = response.choices[0].message.content
            span.set_output(synthesis)
            return synthesis
    
    async def cleanup(self):
        await self.telemetry.flush()
        await self.telemetry.close()

# Use the agent
async def main():
    agent = ResearchAgent()
    result = await agent.research_topic("quantum computing applications")
    print(result)
    await agent.cleanup()

asyncio.run(main())
```

## API reference summary

### Client initialization

<ResponseField name="TelemetryClient" type="class">
Main client class for sending telemetry to RobotForge.

**Constructor parameters:**
- `api_key` (string, required): RobotForge API key
- `user_id` (string, required): User identifier
- `application_id` (string): Application identifier
- `tenant_id` (string): Tenant identifier for multi-tenancy
- `session_id` (string | null): Session identifier
- `batch_size` (integer): Events per batch
- `flush_interval` (float): Seconds between flushes
- `max_retries` (integer): Maximum retry attempts
- `debug` (boolean): Enable debug logging
</ResponseField>

<ResponseField name="trace_model_call" type="async context manager">
Async context manager for tracing model/LLM calls.

**Returns:** `AsyncContextManager[ModelCallSpan]`

**Returns:** `ContextManager[ModelCallSpan]`
